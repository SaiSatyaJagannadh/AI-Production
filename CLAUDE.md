# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

Ed Donner's "AI in Production" course repo. Most of it is **instructional markdown** (`week1/`–`week4/`, `guides/*.ipynb`, `community_contributions/`) that walks a student through building and deploying apps. Only three directories contain runnable code:

| Dir | Stack | Deploy target |
|---|---|---|
| `instant/` | Single-file FastAPI returning HTML | Vercel (`vercel.json` routes all traffic to `instant.py`) |
| `saas/` | Next.js **Pages Router** + TS + Tailwind v4 frontend, FastAPI backend | Vercel |
| `finale/` | Strands agents on AWS Bedrock AgentCore, `uv` project | AWS (`agentcore launch`) |

`week3/` and `week4/` are pointers to other repos (`ed-donner/cyber`, `alex`) — there is no code here for them.

## Commands

```bash
# saas/ (primary app)
cd saas
npm install
npm run dev            # Next.js only — /api will 404, see below
vercel dev             # frontend + Python function together; use this to test the API
npm run build          # type-check + production build
npm run lint           # eslint (flat config, eslint.config.mjs)
vercel --prod          # deploy (project already linked via .vercel/project.json)

# instant/
vercel --prod

# finale/
uv sync
uv run <file>.py                     # local server on :8080
uv run agentcore configure -e <file>.py --region us-west-2
uv run agentcore launch
uv run agentcore invoke '{"prompt": "..."}'
```

There are no tests in this repo.

## saas architecture

The one non-obvious thing: **`saas/api/index.py` is a Vercel Python Serverless Function, not a Next.js API route.** Vercel maps `api/index.py` → `/api`, and the FastAPI route inside it is declared as `@app.post("/api")` (not `/`) because the function receives the full path. Changing that path breaks the frontend call. `npm run dev` does not run it; use `vercel dev`.

Request flow:

1. `pages/product.tsx` gets a Clerk JWT via `useAuth().getToken()`.
2. It POSTs to `/api` with `@microsoft/fetch-event-source` (not `fetch`, because SSE-over-POST needs it) and appends each `ev.data` chunk to a buffer rendered by `react-markdown`.
3. `api/index.py` verifies the JWT with `fastapi-clerk-auth` against `CLERK_JWKS_URL`, then streams OpenAI chunks back as SSE.

**SSE newline quirk:** SSE strips newlines, so `event_stream()` in `api/index.py` re-encodes each newline as a `data:  \n` line (two trailing spaces). The frontend restores line breaks with `remark-breaks`. If markdown rendering suddenly collapses to one paragraph, that encode/decode pair is where to look.

The model prompt lives in `system_prompt` in `api/index.py` and is contractual with the UI: it produces exactly three `###` sections (summary / next steps / patient email), and `pages/product.tsx` splits the stream on those headings.

Auth and billing are both Clerk: `<ClerkProvider>` wraps the app in `pages/_app.tsx`; `<Protect plan="premium_subscription">` in `product.tsx` gates the app behind Clerk's `<PricingTable />`.

### Environment variables

Set locally in `saas/.env.local` **and** in Vercel (`vercel env add <NAME>`) — deploys read only the Vercel-side values:

- `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`, `CLERK_SECRET_KEY` — frontend/Clerk
- `CLERK_JWKS_URL` — backend JWT verification
- `OPENAI_API_KEY` — backend

### Conventions

- Pages Router (`pages/`), not App Router — week 2's material uses App Router, but this app does not. Don't introduce an `app/` directory here.
- Tailwind v4 via `@import "tailwindcss"` in `styles/globals.css`; there is no `tailwind.config.js`. Design tokens are CSS custom properties on `:root` exposed through `@theme inline`.
- `saas/AGENTS.md` is generated by `next dev` and re-added automatically; commit it with your work rather than fighting it. `saas/CLAUDE.md` just includes it.
